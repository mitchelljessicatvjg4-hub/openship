Только что установили Openship? Эта страница поможет запустить ваше первое работающее приложение за четыре простых шага. Openship можно представить как небольшую кухню прямо на вашем компьютере: вы включаете её, открываете дверцу, передаете свой код, а она готовит и подает блюдо. Не нужно арендовать серверы или вручную писать сложные конфигурационные файлы.

<Callout title="Что вам потребуется">
- Компьютер под управлением macOS, Linux или Windows.
- Исходный код, который вы хотите запустить — репозиторий GitHub или локальная папка на диске.
- Никаких арендованных серверов и файлов конфигурации — Openship работает прямо на вашей машине. (На Linux автоматически используется Docker, если он установлен; в противном случае запускается легковесный изолированный процесс).
</Callout>

<Steps>

<Step>

### Установите Openship CLI

CLI — это компактная утилита командной строки. Скопируйте строку для вашей операционной системы и выполните её в терминале:

<InstallTabs />

Если вы используете пакетный менеджер, можно установить через `npm i -g openship` (или `pnpm`, `yarn`, `bun`) — для этого потребуется **Node 22+**, так как утилита будет использовать системную среду Node.
Все варианты установки — настольное приложение, облако, Docker Compose — описаны на странице [Установка](/ru/docs/getting-started/installation).

</Step>

<Step>

### Настройте Openship

```bash
openship
```

Запустите команду **`openship`** без аргументов — интерактивный мастер проведет вас по шагам: создание **учетной записи администратора** (имя, email, пароль), затем выбор режима инстанса: приватный (только на этом компьютере) или публичный (собственный домен + HTTPS). Openship развернет окружение, установит себя как фоновую службу (автозапуск при перезагрузке) и выведет URL для входа. **API** запускается на порту `:4000`, а **панель управления** — на `:3001`. В Linux при наличии Docker разворачивается полный стек (Postgres, Redis и OpenResty для доменов и TLS); в остальных случаях — компактный процесс со встроенной базой данных. Больше ничего настраивать не нужно.

<Callout title="Скрипты или CI? Запуск без диалогов" type="info">
Команда `openship up` выполняет ту же установку **без** мастера (аккаунт администратора не создается — вы регистрируете первую учетную запись прямо в панели управления). Команда `openship up --foreground` запускает процесс с выводом логов в терминал (Ctrl-C для остановки); `openship stop` останавливает службу.
</Callout>

<Callout title="Нужна версия без терминала и авторизации?" type="info">
[Настольное приложение (Desktop)](/ru/docs/getting-started/installation) работает на вашем компьютере только пока открыто окно приложения и не требует входа в систему.
</Callout>

</Step>

<Step>

### Откройте панель управления

```bash
openship open
```

Команда откроет панель управления в браузере по адресу `http://localhost:3001`. **Войдите под учетной записью администратора, созданной во время настройки.** Инстанс, запущенный через CLI, всегда защищен паролем — только [десктопная версия](/ru/docs/getting-started/installation) работает в режиме без авторизации. (Если вы использовали `openship up` вместо интерактивного мастера, зарегистрируйте первый аккаунт в открывшемся окне).

</Step>

<Step>

### Разверните приложение

В панели управления нажмите кнопку создания проекта и укажите источник кода — репозиторий GitHub или локальную папку на диске. Openship проанализирует исходный код, определит тип приложения (стек, фреймворк) и покажет сводку параметров. Для большинства проектов менять ничего не нужно: просто нажмите **Deploy**.

Откроется экран сборки с прямой трансляцией логов в реальном времени. По завершении сборки появится рабочая ссылка. Нажмите на неё, и ваше приложение откроется в браузере! 🎉

</Step>

</Steps>

## Использование через CLI

Развертывать проекты можно и не открывая браузер. Сначала создайте проект в панели управления, затем перейдите в папку с кодом:

```bash
cd your-project
openship init         # выберите, к какому проекту привязать эту папку
openship deploy       # соберите и опубликуйте приложение онлайн
```

Команда `openship init` создает небольшой конфигурационный файл `.openship/project.json`, чтобы последующие команды знали целевой проект. Флаг `--watch` в `openship deploy` позволяет следить за выводом логов сборки до её завершения.

## Решение проблем

<Callout title="`openship open` сообщает, что API не отвечает" type="warn">
Платформа еще не запущена. Сначала выполните `openship up` (подождите несколько секунд до перехода в состояние healthy), затем повторите `openship open`. Проверить текущий статус службы можно в любой момент с помощью `openship status`.
</Callout>

<Callout title="Ошибка сборки (Build failed)" type="error">
Откройте экран сборки и посмотрите последние строки, выделенные красным — там указана точная причина сбоя. При первых деплоях частые причины: неверная команда сборки, отсутствующая переменная окружения или порт, который приложение слушает по умолчанию.
</Callout>

---

Openship предлагает несколько способов установки, и все они приводят к одному и тому же результату. Это можно сравнить с выбором инструмента: вы можете воспользоваться готовым кабелем быстрого старта (скрипт установки), развернуть с помощью уже знакомых инструментов (npm), запустить готовое приложение из коробки (десктопная версия) или стационарно смонтировать систему на сервере (Docker Compose). Выберите подходящий вариант — перейти на другой можно в любой момент.

<Callout title="Какой вариант выбрать?">
- **Хотите быстро попробовать на своём компьютере?** Используйте **скрипт установки (Install script)**.
- **Уже установлены Node.js и npm?** Установите CLI через **npm**.
- **Хотите графический интерфейс без терминала?** Скачайте **десктопное приложение (Desktop app)**.
- **Настраиваете VPS или сервер для постоянной работы? (Рекомендуется)** Установите через **Docker** — либо стек **Docker Compose**, приведенный ниже, либо через CLI (`openship up`), который **по умолчанию использует Docker/Compose на Linux VPS**. Установка без контейнеров (**bare**, встроенная база данных) также полностью поддерживается — см. [Compose vs bare](#run-openship).
</Callout>

## Установка

<Tabs items={['Скрипт установки', 'npm', 'Из исходников (dev)', 'Настольное приложение', 'Docker Compose']}>

<Tab value="Скрипт установки">

Самый быстрый способ. Одна команда устанавливает утилиту `openship` как автономный пакет с проверкой контрольной суммы, работающий под **Node** — используется системная Node, если она достаточно свежая, либо автоматически скачивается официальная сборка Node специально для Openship, не затрагивая ваши глобальные инструменты. Предварительно устанавливать Node или npm не требуется.

```bash
curl -fsSL https://get.openship.io | sh
```

В **Windows** выполните эту команду в PowerShell:

```powershell
irm https://git.openship.io/windows | iex
```

<Callout title="Фиксация версии (Pin version)" type="info">
Хотите установить конкретный релиз вместо последнего? Задайте переменную `OPENSHIP_VERSION` для команды `sh` — а не для `curl` — например: `curl -fsSL https://get.openship.io | OPENSHIP_VERSION=0.1.9 sh`.
</Callout>

<Callout title="Команда openship не найдена после установки?" type="info">
Установщик добавляет путь к бинарным файлам Openship в ваш `PATH`. Если оболочка всё ещё не находит `openship`, откройте новый терминал (или на macOS/Linux выполните `export PATH="$HOME/.openship/bin:$PATH"`) и повторите попытку.
</Callout>

После завершения переходите к разделу [Запуск Openship](#run-openship).

</Tab>

<Tab value="npm">

Если у вас уже установлен **Node.js 22 или новее** и пакетный менеджер, установите CLI глобально:

```bash
npm i -g openship
```

```bash
pnpm add -g openship     # pnpm
yarn global add openship  # yarn
bun add -g openship       # bun
```

Это предоставит ту же команду `openship`, что и скрипт установки. Переходите к разделу [Запуск Openship](#run-openship).

<Callout title="Установлена более старая версия Node?" type="info">
Это единственный способ установки, работающий на **вашей системной** версии Node. Если запустить `openship` на старой версии, утилита предложит скачать официальную сборку Node 22 (~50 МБ) в каталог `~/.openship/runtime` исключительно для работы Openship, оставив системную версию без изменений.
</Callout>

<Callout title="Обновили Node и потеряли команду openship?" type="info">
Менеджеры версий (nvm, fnm, volta) хранят глобальные пакеты отдельно для каждой версии Node. После смены версии просто переустановите CLI:

```bash
npm i -g openship
```
</Callout>

</Tab>

<Tab value="Из исходников (dev)">

Хотите протестировать предварительную сборку — ветку, тег или актуальный коммит из `main`? Эта команда собирает CLI **из исходного кода** и устанавливает как **отдельную команду `openship-dev`**:

```bash
curl -fsSL https://get.openship.io/dev | sh
```

Выбрать конкретную ветку или тег можно с помощью переменной `OPENSHIP_REF` (по умолчанию `main`):

```bash
curl -fsSL https://get.openship.io/dev | OPENSHIP_REF=my-branch sh
```

Сборка из исходников работает **полностью изолированно** от рабочей версии: собственный домашний каталог (`~/.openship-dev`), свои порты, токены и база данных.

```bash
openship-dev            # интерактивная настройка
openship-dev up         # локальный запуск
openship-dev update     # получение свежего кода и пересборка на месте
```

</Tab>

<Tab value="Настольное приложение">

Настольное приложение включает всё необходимое — API, панель управления и базу данных — в виде единого приложения для вашей операционной системы. Никаких серверов и Docker: идеально для локальной разработки и деплоя прямо из папок на вашем компьютере.

Если CLI уже установлен, загрузить и запустить приложение можно одной командой:

```bash
openship install
```

Либо скачайте установщик напрямую для вашей системы:

- **macOS** — [Apple Silicon](https://github.com/oblien/openship/releases/latest/download/Openship-arm64.dmg) · [Intel](https://github.com/oblien/openship/releases/latest/download/Openship-x64.dmg)
- **Windows** — [Openship-win32-x64.zip](https://github.com/oblien/openship/releases/latest/download/Openship-win32-x64.zip)
- **Linux** — [Openship.AppImage](https://github.com/oblien/openship/releases/latest/download/Openship.AppImage)

Также файлы доступны на [странице загрузок](/download).

В **Linux** сделайте файл AppImage исполняемым и запустите:

```bash
chmod +x Openship.AppImage
./Openship.AppImage
```

</Tab>

<Tab value="Docker Compose">

Предпочитаете запускать контейнеры на сервере самостоятельно? Стек для самостоятельного хостинга находится в файле **`docker/docker-compose.yml`** и **скачивает** готовые образы из GitHub Container Registry:

```bash
git clone https://github.com/oblien/openship.git
cd openship
cp .env.example .env          # укажите свои секретные ключи внутри
docker compose --env-file .env -f docker/docker-compose.yml up -d
```

Стек запускает пять сервисов: **Postgres**, **Redis**, **API** (`:4000`), **панель управления** (`:3001`) и пограничный прокси **OpenResty edge** на портах **:80/:443**, управляющий маршрутизацией и выпуском сертификатов Let's Encrypt.
После запуска откройте панель управления по адресу `http://localhost:3001`.

</Tab>

</Tabs>

## Запуск Openship

Если вы установили CLI, самый быстрый способ начать — интерактивная настройка:

```bash
openship
```

Без аргументов команда `openship` задаст основные вопросы: приватный или публичный инстанс, доменное имя, а также **имя, email и пароль администратора**. Затем служба будет развернута, администратор зарегистрирован, а в консоль выведен URL для входа.

Если хотите запустить службу сразу без диалоговых окон:

```bash
openship up
```

<Callout title="Compose или bare — автоматический выбор" type="info">
В **Linux с установленным Docker** Openship по умолчанию разворачивает контейнерный стек (Postgres, Redis, API, панель управления и OpenResty edge на портах :80/:443), способный **размещать ваши приложения прямо на этой машине** с поддержкой доменов и TLS. Это **рекомендуемый режим для VPS**. В остальных случаях (macOS, Windows или Linux без Docker) запускается легковесный процесс со встроенной базой данных. Принудительно задать режим можно флагами `openship up --compose` или `openship up --bare`.
</Callout>

Openship регистрируется как **фоновая системная служба, которая запускается при старте системы и перезапускается при сбоях**.

```bash
openship stop              # остановить службу
openship up --foreground   # запуск с выводом логов в текущий терминал (остановка по Ctrl-C)
openship up --no-ui        # запуск только API, без панели управления
openship uninstall         # удаление Openship и его данных
```

### Управление хостом (Host control)

Панель управления может взаимодействовать с машиной, на которой она запущена: освобождать порты `80`/`443` от стороннего прокси, проверять порты и открывать терминал хоста. В контейнерном стеке это происходит через автоматически сгенерированный SSH-ключ к хосту через мост `host.docker.internal`.

При необходимости этот доступ можно отключить:

```bash
openship up --no-host-control
```

В этом режиме доступ к хосту блокируется, а текущая машина перестает предлагаться в качестве цели для деплоя приложений.

### Удаление Openship

Команда `openship stop` приостанавливает работу, но сохраняет базу данных, выданные сертификаты и конфигурацию. Для полного удаления:

```bash
openship uninstall                 # удаление стека, данных и директории ~/.openship
openship uninstall --keep-data     # удаление только контейнеров с сохранением базы и сертификатов
openship uninstall --keep-images   # удаление без очистки образов контейнеров
openship uninstall --yes           # удаление без запроса подтверждения (для скриптов)
```

При удалении ваши развернутые пользовательские приложения **продолжают работать**. Удаление платформы управления не останавливает запущенные контейнеры ваших проектов.

## Проверка работоспособности

Когда инстанс запущен, откройте панель управления в браузере:

```bash
openship open
```

Или проверьте статус API прямо из терминала:

```bash
openship status
```

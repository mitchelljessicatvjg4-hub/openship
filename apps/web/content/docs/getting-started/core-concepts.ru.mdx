Openship использует несколько ключевых понятий, которые регулярно встречаются в документации и интерфейсе. Если представить ваш исходный код как **рецепт**, то Openship — это **кухня**, а приведенные ниже понятия — ее составные части. Эта страница представляет собой краткий глоссарий основных идей простыми словами.

## Организация (рабочее пространство)

*Совместное пространство для вас и вашей команды.*

Всё, что вы создаете в Openship, находится внутри **организации** (в панели управления также называется рабочим пространством или workspace). Ваши проекты, серверы и домены принадлежат организации, а не конкретному пользователю. Это позволяет совместно работать над инфраструктурой всей командой.

Пользователь может входить в несколько организаций одновременно. У каждого участника есть **роль**: владелец (owner), администратор (admin) или участник (member). Роль определяет доступные права и действия. Подробнее в разделе [Права доступа](/ru/docs/security/permissions).

## Проект (Project)

*Отдельное приложение, доступное онлайн.*

**Проект** — это отдельное приложение, которое вы развертываете. Проект хранит источник кода (репозиторий GitHub или локальную папку на диске), параметры сборки, историю деплоев, веб-адреса, переменные окружения, логи и настройки.

Большую часть параметров не нужно настраивать вручную — Openship определяет стек приложения и подставляет подходящие значения по умолчанию. Создание проекта описано в [Быстром старте](/ru/docs/getting-started/quickstart).

## Окружение (Environment)

*Раздельные рабочие площадки для боевой версии и тестирования.*

**Окружение** — это изолированная копия вашего проекта. Чаще всего используются:

- **Production (Боевое)** — основная версия, с которой работают реальные пользователи.
- **Preview (Предпросмотр)** — временная копия для проверки изменений перед выпуском в релиз.

Также доступно окружение **Development** для локальной разработки. Каждое окружение имеет собственные деплои, свои переменные окружения и отдельный веб-адрес, благодаря чему тестирование никогда не влияет на боевую систему.

## Деплой (Deployment)

*Конкретная версия сборки и публикации проекта.*

**Деплой** — это единичная попытка собрать ваш код и запустить его. При каждом деплое (или при каждом push в GitHub при включенном автодеплое) Openship создает новую запись деплоя. Каждому успешному выпуску присваивается номер версии (v1, v2, v3…), чтобы их можно было легко различать.

В каждый момент времени активным (**live**) является только один деплой. Предыдущие версии сохраняются в истории, и в случае сбоя нового релиза вы можете мгновенно выполнить **откат (rollback)** на предыдущую рабочую версию.

## Сервис (Service)

*Рабочий компонент приложения.*

Большинство проектов представляют собой одно приложение. Однако сложные системы состоят из нескольких совместно работающих компонентов — например, веб-приложение, база данных и кэш. Каждый такой компонент является **сервисом**. Openship поддерживает два варианта:

- **Compose** — сервисы, описанные в файле `docker-compose` (например, `web`, `db` и `redis`).
- **Monorepo** — несколько приложений в одном репозитории, каждое из которых собирается как отдельный сервис.

Сервисы могут зависеть друг от друга, иметь собственный публичный адрес или оставаться приватными, а единый деплой запускает всю группу согласованно. Подробнее в руководстве [Multi-service & Compose](/ru/docs/guides/compose-multi-service).

## Домен (Domain)

*Адрес вашего приложения в сети.*

**Домен** — это веб-адрес, по которому пользователи открывают ваше приложение (например, `app.example.com`). Openship может предоставить бесплатный поддомен для быстрого старта, а также подключить собственный домен.

При добавлении собственного домена Openship проверяет DNS-записи и автоматически выпускает бесплатный сертификат Let's Encrypt HTTPS. Один из доменов помечается как **основной (primary)**.

## Сервер (Server)

*Физическая или виртуальная машина для размещения приложений.*

**Сервер** — это удаленный компьютер (VPS, выделенный сервер), к которому Openship подключается по SSH для запуска ваших приложений. Сервер добавляется один раз с реквизитами подключения (хост, пользователь, ключ или пароль), после чего Openship может развертывать на нем сервисы. В одной организации может быть зарегистрировано несколько серверов.

<Callout title="Сервер нужен только для среды выполнения 'server'" type="info">
Если вы развертываете проекты локально или в Openship Cloud, добавлять сервер не требуется. Серверы нужны только для запуска приложений на вашей собственной инфраструктуре.
</Callout>

## Среды выполнения (Runtimes)

*Выбор целевой площадки запуска.*

При деплое вы выбираете, **где именно физически исполняется приложение** (deploy target):

- **Локально (Local)** — на том же компьютере, где запущен Openship.
- **Собственный сервер (Your server)** — на одном из ваших подключенных серверов по SSH в контейнерах Docker.
- **Openship Cloud** — полностью управляемая облачная среда Openship.
